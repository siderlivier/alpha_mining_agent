# 台股 Alpha 因子挖掘 Agent

自我進化的因子挖掘系統：**LLM 提出假設 → 本地 Python 驗證 → 經驗蒸餾回記憶 → 下一輪用得上**。
LLM 只負責提假設與寫檢討，所有數字都由本地程式算，agent **看不到測試期的任何指標**。

跑了 1043 輪嘗試，26 個自有因子入庫。合上前置專案的 25 個參考因子後，
51 因子 + LightGBM 在 2020-01 ~ 2026-06 的樣本外測試期得到**年化超額 16.36%、IR 2.57**。

- 完整設計理由 → `SPEC_架構設計規格書.md`
- 逐項功能、參數、疑難排解 → `GUIDE_使用教學.md`
- **所有實測數字與產生它的指令 → `RESULTS.md`**（16 節，含一次結論被推翻的完整紀錄）

**別只看 CAGR。** 台股這段測試期本身就是大多頭，等權基準的 CAGR 就有 24.26%。

## 方法論：怎麼確保這些數字不是自己騙自己

這是本專案投入最多的部分。一個漂亮的 IR 有很多種假法，每一種需要不同的方法拆穿。

### 1. 前瞻偏差：四層獨立防護，而且每一層都做過變異驗證

| 層 | 檔案 | 檢查什麼 |
|---|---|---|
| DSL 語言層 | `test_dsl_no_lookahead.py` | 33 個運算子逐一驗證 |
| 全管線 | `test_pipeline_no_lookahead.py` | 資料 → 漏斗 → 診斷 |
| 因子合成 | `test_factor_lab.py` | walk-forward + embargo、橫斷面標準化 |
| 市場狀態模型 | `test_hmm_regime.py` | 時點對齊、前向濾波、狀態標籤 |

共同手法：**汙染 cut 之後的資料，斷言 cut 之前的輸出位元級相同**（`check_exact=True`，不給容差）。

光有測試不夠——**測試本身也可能是假的**。每一道都做過變異驗證，故意寫錯確認它會轉紅：

```
把 walk_forward 的訓練窗改成全期       → test_walk_forward_no_lookahead              轉紅
把 embargo 拿掉                       → test_segments_embargo_gap                    轉紅
把 forward_filter 換成 predict_proba   → test_forward_filter_is_causal                轉紅
把 market_series 的 shift(1) 拿掉      → test_market_series_lags_observations_by_one  轉紅
```

這件事不是形式主義。專案初期就抓到 `test_pipeline_no_lookahead` 的汙染點寫死了 index、
落在 `sub_train` 內部——**測試自己在製造假陽性**，整套前瞻檢測形同虛設。

DSL 層的做法是**語言級封鎖**：可用欄位、視窗、AST 深度都是白名單，
表達不出「看未來」的公式，而不是事後檢查。新增運算子時**必須**在
`tests/test_dsl_no_lookahead.py` 的 `FORMULAS` 加一條用到它的公式，
否則 `test_all_operators_covered` 直接失敗。

### 2. 密封的測試期

`library.json` 裡每個因子都有 `test_metrics_sealed`，**絕不進入任何 prompt**。
agent 只能看到 `sub_train` 與 `validation` 的指標。因子的攻擊／防禦分類、
狀態模型的參數與標籤，也全部只用 ≤ `validation` 末端的資料決定。

### 3. 選擇偏誤：walk-forward 保護的是參數，不是「選哪些因子」

這一點很容易漏。用 test 期的 IR 挑因子、再用 test 期的 IR 當成績，就是拿答案卷挑答案。
`--greedy` 因此拆成 `--select-span`（在哪裡挑）與 `--span`（在哪裡報）：

| 做法 | 挑選期 | test 期 IR | test 期超額 |
|---|---|---|---|
| **全部 26 個，不挑** | — | **1.583** | **10.72%** |
| 貪婪挑 k=3 | validation | 1.425 | 8.47% |
| ~~貪婪挑 k=10~~ | ~~test~~ | ~~2.264~~ | ~~12.04%~~ ← 假的 |

挑出來的組合在 validation 期 IR 高達 4.406，到 test 期只剩 1.425——
**那 4.4 是 24 個月樣本上的噪音**。結論是別挑：全部用比任何挑出來的子集都好。
不帶 `--select-span` 時程式會在結尾印警告。

### 4. 過擬合統計量，以及它們的但書

```
Deflated Sharpe：0.997
  樣本外月數 T = 77　試驗數 N = 54（51 個單因子 + 3 個合成模型）
  主動報酬月 Sharpe 0.742（年化 2.57）　去膨脹門檻 SR0 = 0.398（年化 1.38）
PBO（CSCV，S = 12 切塊，C(12,6) = 924 組）：0.001
```

DSR 的讀法：試 54 個策略，光靠運氣，期望中最好的那個年化 Sharpe 就有 1.38；
實測 2.57 遠高於門檻。⚠️ 必須用**主動報酬**（超額）而非原始報酬——
不減基準的話所有策略都吃同一份多頭 beta，試驗集的 Sharpe 變異被壓縮，門檻被低估，DSR 虛高。

> ⚠️ **PBO 0.001 要打折扣看。** 母體裡 51 個是單因子、只有 3 個是合成模型，
> 而合成模型在任何切塊都穩定勝過單因子——樣本內最佳幾乎總是模型，樣本外也是，
> PBO 於是趨近 0。它說明的是「合成勝過單因子」很穩健，**不是**「這組超參數沒過擬合」。
> 程式會在 PBO 過低時自動印出這段警告。

### 5. 一次真實的判讀錯誤：用 IR 去評判一個 beta 決策

這是本專案最值得記錄的一段，因為**沒有任何測試能抓到它**。

市場狀態切換模組原本被判定失敗：IR 從不切換的 1.74 掉到 1.08。
`TODO.md` 寫上「結案，結論是負面的」，`RESULTS.md` 第 11 節整節都在解釋它為什麼失敗。

**程式完全正確。** IR 算對了、beta 算對了、前瞻防護全部有效、當時全部測試皆綠。
錯的是**拿 IR 去判斷一個 beta 決策**這個判讀層面的選擇。

IR = 超額 / 追蹤誤差，是**相對基準**的指標；而切換的本質是降低 beta。
在一段基準年化 +24.26% 的測試期裡，任何降 beta 的動作都會讓相對基準的超額下降，
IR 必然扣分——**即使那個動作在風險調整後是賺的**。

換成對曝險免疫的 Sharpe（加槓桿 k 倍時分子分母同乘 k）之後，結論反轉。
`--riskadj` 現在把這個檢定做成三張表：**原始指標 + Sharpe/TE**、**等 beta 對照**、
**配對自助法信賴區間**。詳見下方「市場狀態模型」與 `RESULTS.md` 第 16 節。

診斷方式很簡單，之後遇到任何「兩個指標打架」都適用：

1. **先確認 alpha 有沒有變。** 沒變就代表動到的是曝險，不是技術。
2. **把曝險調成一樣再比。** 加槓桿或減倉，然後看每一欄。
3. **看對曝險免疫的指標。** 相對指標不能用來評判刻意的曝險決策。
4. **算信賴區間。** 77 個月能不能分辨 1.79 與 1.88？答案是不能。

## 三個必須說出口的但書

**一、可交易性有代價。** 只看最流動 30% 的股票時：

| 版本 | 年化超額 | IR | 月勝率 | 下跌月最好 3 個月佔總超額 |
|---|---|---|---|---|
| 全體股票池 | 16.30% | 2.55 | 84.4% | 33% |
| 可交易版（最流動 30%） | 15.10% | **1.16** | **58.4%** | **58%** |

**超額的水準守得住，穩定度守不住。** 持股從 84 檔縮到 24 檔，集中度大幅上升，
2022 與 2023 年小幅為負。而且下跌月的超額有 58% 來自最好的 3 個月
（2020-12、2020-02、2022-05，其中兩個在疫情初期的極端行情）——
拿掉這 3 個月，下跌月 IR 從 1.34 崩到 **0.78**。
**這是整套診斷裡最該記住的一格。**

對照之下全體股票池是廣泛的：27 個下跌月有 23 個超額為正，
中位數 +1.08% 與平均 +1.09% 幾乎相同（分布不偏斜），
拿掉最好的 3 個月 IR 只從 2.78 掉到 2.42。

**二、六項檢定共用同一段歷史。** régime、breadth、liquidity、importance、DSR/PBO、cost
各自獨立地檢查不同的失效模式，但它們全都在 2020-01 ~ 2026-06 這 77 個月上做。
**真正的樣本外只有一種：往前走。**

**三、沒有產業輪動、沒有市場擇時，永遠 100% 投資。**
回測逐月「在各產業內」取前 10%，產業權重結構性地鎖在全池比例上
（持股 60.6% 電子 vs 全池 59.9%，四個產業偏離都在 ±0.7% 內）。
全部超額都來自產業內選股這**單一**來源。

## 穩健性診斷結果（`src/ml_diagnose.py`）

| 假法 | 拆穿的方法 | 結果 |
|---|---|---|
| 只是搭上多頭順風車 | 分多空 régime | 下跌月超額 **+13.08%**（IR 2.78、t 4.17、勝率 85.2%），比上漲月的 IR 2.53 還高；七年逐年超額全正 |
| 只是少數幾個月撐起來 | 逐月攤開 + 拿掉最好 3 個月 | 全體 IR 2.78 → 2.42；可交易版 1.34 → **0.78**（見但書一） |
| 只是小型股／低流動溢酬 | 剔除底 70% 低流動股 | 超額仍有 **15.09%**（原 16.28%）；持股流動性百分位平均 0.42 |
| 只是規模因子換個名字 | 規模中性版重跑 | IR 2.57 → 2.14（−16.9%），**與「隨機拿掉一個重要因子」的中位掉幅 16.9% 相同** |
| 只是試很多策略挑到的幸運兒 | Deflated Sharpe / PBO | DSR **0.997**、PBO 0.001（有但書） |
| 報酬被換手成本吃光 | 成本敏感度 | 成本拉到 1.6%（設定值四倍）仍有 **6.68%** 超額；等權此時已翻負 |

規模代理的偵測用了**兩道判準**：相關度與公式。
F-013 `sub(cs_rank(rev_yoy), cs_rank(amt_21))` 與
F-020 `mul(cs_rank(op_margin), cs_rank(neg(amt_21)))`
公式裡明明白白寫著 `amt_21`，量測相關度卻低於 0.6 門檻。
**相關度是行為證據，公式是定義證據，兩道都要。**

成本敏感度還提供了一次乾淨的驗證：衰退幅度 = 換手 × Δ成本 × 12，
lgbm 的 `0.672 × 0.014 × 12 = 11.29%` 與實測完全吻合 → 持股不隨成本改變。

### 留一法：組合擁擠度本身就是訊號

`Δ貢獻 = 全集 IR − 去掉該因子後的 IR`，負值代表拿掉它反而更好。

26 個自有因子（Ridge，全集 IR 1.583）只有 **5 個**是拖累者；
主要支柱是 F-026 金控效率重估（Δ **+0.417**）與 F-009 營收加速趨勢（+0.250）。

但 51 個因子的 all 組（全集 IR 1.663）被標成拖累的有 **33/51**。
那不代表 33 個是垃圾，而是這組因子**過度擁擠**——邊際貢獻趨近零、正負號落在噪音裡。
此時該讀的是**排序**而非正負號。`--loo` 是診斷工具，不是選股清單產生器。

## 市場狀態模型（`src/hmm_regime.py`）

Gaussian HMM 判斷下個月是多頭態還是空頭態。用途**不是決定進出場**，而是**切換因子組**。

### 為什麼是切換因子而不是擇時

擇時的門檻高得離譜（`--timing`）：test 期有 **65%** 的月份上漲，
「永遠猜漲」這個零成本策略就有 65% 準確率，且績效**就是**目前滿倉的績效。
要贏過滿倉需要 **80%** 的方向準確率（1000 次模擬，勝過滿倉的機率 49.3%）。

切換因子的門檻低得多，因為**失敗的代價低一個量級**：
進出場猜錯 = 整月不在場；因子權重猜錯 = 用了比較不合適的那組因子（IC 仍為正），只是少賺一點。

而且有值得利用的結構（`--regime-factors`）。低波動族群呈現極強的不對稱，
**兩個期間都成立**（括號為 t 值 = ICIR × √月數）：

| 因子 | 名稱 | 分類期 ICIR_漲 | 分類期 ICIR_跌 | test ICIR_漲 | test ICIR_跌 |
|---|---|---|---|---|---|
| R-004 | 低波動（半年） | +0.29 (2.22) | +2.14 (**12.11**) | −0.15 (−1.03) | +1.71 (**8.88**) |
| R-006 | 低波動（月） | +0.34 (2.64) | +1.61 (**9.51**) | −0.12 (−0.87) | +1.89 (**9.82**) |
| F-008 | 低調接近新高 | +0.02 (0.17) | +1.57 (**8.31**) | −0.31 (−2.19) | +1.60 (**8.30**) |

**下跌月的強度壓倒性且穩定（t = 8~12）；上漲月兩期都貼近零。**
test 期有 12/51 個因子「漲跌變號」，但那不是結構改變——
只是上漲月的雜訊翻面（|t| 大多 < 1.1）。**穩定的是不對稱本身，不是正負號。**

### 結果：以 Sharpe 論達標，但差距不顯著

防禦組 = 依「分類期下跌月 ICIR 的 t 值」取前 8 個，**完全不看 test 期**。

```bash
python src/hmm_regime.py --riskadj      # 三張表：原始指標 / 等 beta 對照 / 自助法
python src/hmm_regime.py --ablate       # 特徵消融（多 seed 取中位數）
python src/threshold_sweep.py           # 門檻掃描
```

**A. 原始指標**（test 期 77 個月，基準 CAGR 24.26%）：

| | beta | alpha | CAGR | Vol | **Sharpe** | 超額 | TE | IR | MaxDD |
|---|---|---|---|---|---|---|---|---|---|
| 靜態：全部因子 | 0.932 | +13.27% | 39.32% | 19.91% | **1.79** | +11.63% | 6.70% | 1.74 | −15.59% |
| 靜態：只用防禦組 | 0.711 | +9.75% | 28.82% | 15.37% | 1.74 | +2.83% | 8.02% | 0.35 | −13.16% |
| **HMM 切換（樣本外）** | 0.791 | +13.52% | 35.80% | 17.29% | **1.88** | +8.52% | 7.87% | 1.08 | −13.16% |
| 完美預知（上限） | 0.874 | +16.97% | 42.82% | 18.84% | **2.01** | +13.97% | 7.05% | 1.98 | −13.16% |

**兩個指標指向相反方向**：IR 說切換輸（1.08 < 1.74），Sharpe 說切換贏（1.88 > 1.79）。
而 **1.79 < 1.88 < 2.01** 落在「不切換」與「完美預知」之間，正是當初訂下的驗收區間。
切換的 Sharpe 同時高於兩個端點（全部因子 1.79、一直防禦 1.74），不是單純的內插。

超額分解說明了差異的來源（`超額 ≈ alpha + (beta−1) × 基準`）：
切換的超額少了 3.11pp，其中 **3.41pp 來自 beta 貢獻變得更負，alpha 反而多了 0.25pp**。
**切換沒有傷到 alpha，它只是賣掉了 beta。**

**B. 等 beta 對照**——用 rf = 0 融資把切換版放大 1.178 倍（= 0.932 / 0.791）：

| | beta | alpha | CAGR | Sharpe | IR | MaxDD |
|---|---|---|---|---|---|---|
| 靜態：全部因子 | 0.932 | +13.27% | 39.32% | 1.79 | 1.74 | −15.59% |
| **HMM 切換 ×1.178** | 0.932 | +15.92% | **42.86%** | 1.88 | **1.80** | −15.50% |

等 beta 之後每一欄都不輸。原本 IR 1.08 vs 1.74 的巨大落差，**完全是曝險差異**。

> ⚠️ 但 **MaxDD 的好處也一起消失了**。A 表裡切換的 −13.16% 比靜態好 2.4pp，
> 等 beta 之後回到 −15.50%。那是曝險低造成的，不是擇時擋掉了什麼——
> 想要那個回檔，把靜態組合縮到 0.79 倍就有，不需要 HMM。
>
> ⚠️ 1.178 倍要真的借錢。以融資成本 3% 計約吃掉 0.53pp/年（CAGR → ~42.3%），仍高於 39.32%。

**C. 這個差距分得出來嗎？**（配對自助法，逐月重抽 10000 次）

| 統計量 | 點估計 | 95% CI | P(Δ > 0) |
|---|---|---|---|
| ΔSharpe（靜態 − 切換） | −0.091 | **[−0.347, +0.152]** | 0.232 |
| ΔIR（靜態 − 切換） | +0.654 | [−0.060, +1.460] | 0.965 |

逐月報酬差年化 +3.11%，配對 t = 1.34。

**ΔSharpe 的信賴區間跨越 0。** 77% 的重抽偏向切換，但沒到 95%。
所以正確的措辭是：**沒有證據顯示切換比較差，也沒有足夠證據顯示它比較好。**
n = 77 分不出 1.79 與 1.88。

### 門檻掃描：結論不依賴參數

預設門檻 0.5 是個沒調過的值。若結論只在 0.5 成立，那是巧合不是結論。

| 純價格 @門檻 | 0.1 | 0.2 | 0.3 | **0.5（預設）** | 0.7 |
|---|---|---|---|---|---|
| **Sharpe** | 1.82 | **1.95** | 1.89 | **1.88** | 1.85 |
| IR | 1.28 | 1.34 | 1.13 | 1.08 | 0.98 |
| 看多月數 | 58 | 50 | 46 | 42 | 39 |

**五個門檻全部勝過基準的 1.79，而 IR 在同一批設定上全部落後 1.74。**
兩個指標在五個獨立參數點上系統性地指向相反方向——
這是「指標選擇本身就是一個結論」的直接證據。

> ⚠️ **不要挑 @0.2 的 1.95 來用。** 在 test 期挑最好的門檻，就是上面 `--greedy`
> 那個選擇偏誤的翻版。這張表支持的結論只有一個：**結論不依賴門檻**（五個都贏），
> 而不是「最佳門檻是 0.2」。該引用的是未調過的預設值 **0.5 → 1.88**。

### 消融：四種總經指標，一個都沒幫上忙

抓了景氣對策信號（分數＋燈號）、領先指標、M1B/M2 黃金交叉，共 3992 列月頻資料。
每組跑 3 個 seed 取中位數（± 為全距的一半）：

| 特徵組合 | 看多月數 | **Sharpe** | IR | alpha | beta | CAGR |
|---|---|---|---|---|---|---|
| 靜態：不切換 | — | 1.79 | 1.74 | 13.27% | 0.932 | 39.32% |
| **純價格（對照組）** | 42 | **1.88** ±0.00 | 1.08 | 13.52% | 0.791 | 35.80% |
| ＋景氣燈號 | 45 | 1.84 ±0.03 | 0.88 | 11.87% | 0.770 | 33.13% |
| ＋景氣對策信號分數 | 40 | 1.82 ±0.03 | 0.85 | 11.59% | 0.771 | 32.80% |
| ＋M1B−M2 交叉 | 56 | 1.78 ±0.03 | 1.07 | 12.65% | 0.830 | 35.65% |
| ＋全部總經 | 42 | 1.76 ±0.00 | 0.67 | 10.61% | 0.762 | 31.30% |
| ＋領先指標年增率 | 51 | 1.73 ±0.00 | 0.78 | 11.02% | 0.796 | 32.61% |
| 只用總經（無價格） | 72 | 1.68 ±0.01 | 0.92 | 10.66% | 0.844 | 33.44% |
| 完美預知（上限） | 111 | 2.01 | 1.98 | 16.97% | 0.874 | 42.82% |

**每一個加了總經的版本都比純價格差，加得越多越差。** 只用總經是全表最低。
純價格版的 seed 全距是 0.00，不是初始化運氣；加總經的版本全距 ±0.03，
比它們與基準的差距還大——那點差異本來就是雜訊。

**總經特徵不但沒幫上忙，還稀釋了價格訊號。**
這是唯一在 IR 與 Sharpe 兩個裁判下都成立的結論。合理的解釋是發布落後：
月底 t 換股時最多只能用 t−1 月的燈號，而燈號本身就是落後指標的合成。

### 一個非直覺的發現：狀態標籤不能望文生義

訓練期（2012-04 ~ 2019-12，93 個月）擬合出來的兩個狀態：

| 狀態 | 月數 | 觀測報酬均值 | 觀測波動 | → 下月市場報酬 | → 下月上漲比例 |
|---|---|---|---|---|---|
| 低報酬態 | 25 | +0.16% | 6.54% | **+2.56%** | **72.0%** |
| 高報酬態 | 68 | +1.24% | 3.35% | +0.40% | 61.8% |

**高波動狀態之後反而漲得多**（波動的風險溢酬／反彈效應）。
第一版程式照直覺把「過去報酬高、波動低」當多頭態，
結果 test 期方向準確率只有 **35.1%**（基準 64.9%）、t = **−2.33**、p = 0.023——顯著地**反向**。
那不是模型無效，是**標籤貼反了**。

修正方式是用資料決定：`bull_state_from_train()` 在訓練窗內比較各狀態的後續市場報酬，取最高者。
⛔ 只能用擬合當下已實現的月份配對——觀測 `X[j]` 對應 `mkt[idx[j]]`，
後者要下個月底才知道，所以配對只到 `j = n−2`。

修正後方向準確率 49.4%，仍**輸給**「永遠猜漲」的 64.9%（模型太保守，
77 個月只喊 23 個月看多）；但預測看多與看跌兩組的報酬差異是顯著的
（+4.07% vs +1.11%，**t = 2.16、p = 0.036**）。
**方向準確率不足以擇時，但足以切換因子組**——這正好對應前面「失敗代價低一個量級」的設計選擇。

### 三道前瞻紀律

1. **時點對齊**：`obs_ret[t] = mkt[t−1]`。`fwd_ret_1m` 是未來報酬，少 shift 一格就是直接看答案。
2. **只用前向濾波，不用平滑**：`hmmlearn.predict()`（Viterbi）與 `predict_proba()`（平滑）
   都會用整段序列回推每個時點的狀態。本模組**只用 hmmlearn 擬合參數**，狀態推論自己寫遞迴。
3. **參數與標籤只在訓練窗擬合**：擴張窗重擬，測試期永遠只驗證。

總經資料的發布落後寫進資料結構本身（`ym` 描述月份 vs `pub_ym` 已公開月份），
取值一律走 `as_of(panel, t)`。
**新增欄位若忘了在 `PUB_LAG_MONTHS` 登記會直接丟錯，而不是預設 0**——
因為前瞻偏差不會報錯，只會讓回測變好看。

## 系統架構

### 挖礦迴圈

```
Generate（LLM 提假設）→ 四階段漏斗（本地驗證）→ Distill（LLM 寫檢討）→ 記憶
                                                    ↓ 每 10 輪
                                              Consolidate（經驗壓縮 + 運算子提案）
```

**四階段漏斗**：Stage 1 IC 門檻 → Stage 2 與因子庫去相關（ρ ≤ 0.5）→
Stage 3 批次內去相關（ρ ≤ 0.7）→ Stage 4 ICIR／衰減／多空腿／覆蓋率／換手；
Stage 4b 是產業專屬通道，讓只在單一產業有效的因子有機會入庫。

**兩層記憶**：`attempts/` 只進不出（1043 筆完整軌跡）；
`learnings.md` 是唯一注入 prompt 的記憶，由整理回合蒸餾，原文自動備份到 `learnings_history/`。

**運算子提案**：agent 表達不出某個想法時可以提案新運算子。
機械驗證只查名稱格式／純函數簽名／證據引用 ≥2，**不保證語意可用**
（例如 `qtr_only` 通過了驗證，但在月頻面板上會產生 100% NaN），
所以**人工批准前絕不自動實作**。已上線 5 個：
`rank_nz`、`industry_demean`、`streak`、`streak_true`、`clip_std`。
實作完記得跑 `python src/unblock.py --apply`，把當初卡住的假設放回佇列重試。

### 參考因子的四道篩選

前置專案 `tw_alpha_strategy/src/mine_dfs.py` 挖出 86 個 DFS 因子。
不匯入的話 Stage 2 不知道它們存在，agent 會重新發明輪子
（F-005 其實就是 `neg_vol_126`、F-006 幾乎等於 `neg_accruals`）。

篩選四道：沿用上游的 survivors 判準 → `|ICIR_train|` 門檻 → 衰減 ≤ 50%
（與本專案 Stage 4 同標準）→ **參考因子彼此去重**（`--max-ref-corr`，預設 0.95）。
86 → 31 → **25** 個。

**第四道是必要的**，因為前三道都是逐因子判斷，看不到「同一條公式掛兩個名字」。
上游的 `generate()` 有兩個區塊各算了一次獲利率，造成 3 對同公式雙名因子——
證據是 `dfs_candidates.csv` 裡的指標**逐位相同**：

| 因子 A | 因子 B | ICIR_train | ρ |
|---|---|---|---|
| `net_margin` | `ni_to_rev` | 0.5224053537899057 | **1.000** |
| `op_margin` | `op_to_rev` | 0.4596369922253636 | **1.000** |
| `gross_margin` | `gp_to_rev` | 0.1206846955682397 | **1.000** |

兩個都收，等權合成時「淨利率」這個概念就被賦予兩倍權重。
去重後 all 組 IR 從 1.663 升到 **1.741**（Ridge）。
上游已修正並加了 `_assert_no_duplicate_factors()`——用整欄雜湊比對，
`generate()` 回傳前若有任兩欄完全相同就直接丟錯。

參考因子以 `R-xxx` 與自有的 `F-xxx` **同住 `library.json`**，靠 `reference: true` 區分；
`report` / `audit` / 統計走 `own_library()`，不會把它們算成 agent 的成果。
第一次匯入後會存 `data/dfs_snapshot.parquet` 自足快照，**之後不再跨專案調用**。

### 只做多——以及一條沒人讀的腿

`backtest.portfolio_returns()` 算出三條腿，但所有 headline 都取 `long`：

| 腿 | CAGR | Sharpe | MaxDD | 目前 |
|---|---|---|---|---|
| `long` | 45.54% | 1.92 | −16.66% | ✅ 所有 headline |
| `long_short` | 36.69% | **2.63** | **−9.82%** | ❌ 算了但沒人讀 |
| `benchmark` | 24.26% | 1.18 | −17.73% | ✅ 只用來算超額 |

**報酬較低但風險調整後明顯較好**，因為對沖掉了 beta。
空頭腿單獨看年化 **−7.87%**、月勝率 44.2%——後段班相對基準每年輸 16.05%、
78% 的月份都輸（訊號很強），但絕對報酬仍是正的。
**單獨放空賺不了絕對報酬，它的價值在對沖。**
台股放空另有借券成本與平盤下不得放空的限制，這條腿尚未納入成本模型。

## 安裝與使用

```bash
pip install pandas numpy pyarrow pyyaml pytest        # 必要
pip install lightgbm scipy shap hmmlearn              # 選配：合成、DSR、SHAP、狀態模型
```

需要 Claude Code CLI（`claude` 指令可用）與前置專案資料
`../tw_alpha_strategy/data/processed/panel.parquet`。

> 長時間無人值守跑的話，建議改用一年期 token 而非互動登入，避免 OAuth 過期：
> `claude setup-token` → `setx CLAUDE_CODE_OAUTH_TOKEN "<token>"`

### 首次設定（一次性）

```bash
python src/build_base.py                 # panel → 月頻快照（約 1-2 分鐘）
python src/build_regime.py               # 市場狀態表 + 月頻大盤報酬
python src/seed_memory.py                # 初始化空記憶（不預載任何理論）
python src/seed_reference.py --dry-run   # 看參考因子的去重報告
python src/seed_reference.py --apply     # 灌進 Stage 2 的去相關基準
python -m pytest tests/ -q               # 241 passed，約 100 秒
```

### 挖礦

```bash
python src/mining_loop.py --dry-run     # 先看 Generate prompt 長什麼樣
python src/mining_loop.py               # 跑 1 輪（約 8~15 分鐘、$0.9~1.5）
python src/mining_loop.py --rounds 5    # 連跑 5 輪（受週預算自動停）
python src/mining_loop.py --mock        # 假 LLM 跑通管線，不耗額度
python src/mining_loop.py --budget      # 只印本週用量
```

輪次／token／成本三種週預算都在 `config.yaml` 的 `budget` 區塊，
狀態存 `memory/budget.json`，跨 session 自動接續、每週一重置。

### 人工監督（放行自動化前必做）

```bash
python src/query_attempts.py --limit 40          # 瀏覽全部嘗試
python src/query_attempts.py --verdict passed    # 看入庫因子的假設品質
type memory\learnings.md                         # 審核蒸餾出的經驗
```

審核重點：hypothesis 是否有機制（而非套套邏輯）、diagnosis 是否對照了 prediction、
lesson 是否過度泛化。**如果 lesson 品質差，先修 `prompts/` 再繼續**，
不要讓垃圾經驗累積。`learnings.md` 可直接手動編輯修正。

### 分析與診斷

```bash
python src/report.py --html                      # 因子庫總覽（含密封 test 指標，人類專用）
python src/audit.py --human                      # 過擬合審計
python src/factor_lab.py --compare --model equal,ridge,lgbm
python src/factor_lab.py --loo --set own         # 留一法
python src/factor_lab.py --greedy --set own --select-span validation --span test
python src/factor_lab.py --cost-scan --set all --model equal,ridge,lgbm
python src/ml_diagnose.py --all                  # 五項診斷全跑（約 18 分鐘）
python src/ml_diagnose.py --dsr                  # Deflated Sharpe + PBO
python src/hmm_regime.py --riskadj               # 風險調整後對照
```

**合成順序建議 equal → ridge → lgbm。** 等權沒有參數可以過擬合，是誠實的基準；
Ridge 若贏不過等權就別急著上 LightGBM。本專案的實測是三層都有提升
（IR 0.73 → 1.74 → 2.57），所以都留著。

`--span` 預設 `test`，而且**只有 `test` 是真正的樣本外**——
agent 的因子是用 `sub_train` + `validation` 選出來的，
上游 DFS 因子也是用 ≤2019-12 篩的，兩邊 test 期起點相同，比較才公平。選其他期會跳警告。

## 已知的限制

1. **HMM 的優勢不顯著**（ΔSharpe 的 95% CI 跨越 0）。需要更長樣本才能定案。
2. **美債殖利率曲線取不到**。FinMind 的 datalist 認得 `United States 10-Year`
   （官方文件寫成 `10-Year`），但資料端點回空陣列，判定為方案層級或額度限制。
3. **`long_short` 未納入借券成本**與平盤下不得放空的限制，那條 Sharpe 2.63 要打折。
4. **所有檢定共用同一段 test 期**。往前走才是真的樣本外。
