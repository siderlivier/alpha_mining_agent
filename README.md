# 台股 Alpha 因子挖掘 Agent

**自我進化的因子挖掘系統**：LLM 提出假設 → 受限 DSL 寫成公式 → 本地 Python 四階段驗證
→ 檢討蒸餾成經驗 → 下一輪的 prompt 讀得到。跑滿 68 輪、1043 個候選，26 個因子入庫。

LLM 只做兩件事：**提假設**與**寫檢討**。所有數字都由本地程式算，
agent **看不到測試期的任何指標**，也不能碰回測程式碼。

- 完整設計理由 → `SPEC_架構設計規格書.md`
- 逐項功能、參數、疑難排解 → `GUIDE_使用教學.md`
- 所有實測數字與產生它的指令 → `RESULTS.md`（17 節）
- **每個檔案在做什麼 → `FILES_檔案對照表.md`**

## 這個專案跟前置專案差在哪

前置專案 `tw_alpha_strategy` 已經用 DFS（deep feature synthesis）自動組合出 86 個因子，
也有完整的 ML 評估。**那套是窮舉：把欄位兩兩相除、取變化率、排序，能組的都組出來。**

這個專案換一種產生方式：**讓 LLM 先講出一個機制，再把機制寫成公式**。
差別不在「誰的因子多」，而在三件事：

| | 前置專案（DFS 窮舉） | 本專案（LLM 假設） |
|---|---|---|
| 因子從哪來 | 欄位的機械組合 | 先有假設（「為什麼這會有效」），再有公式 |
| 失敗會怎樣 | 丟掉，下次一樣的組合再算一次 | 寫成 lesson 進記憶，下輪 prompt 讀得到 |
| 能表達的東西 | 固定的組合模板 | 33 個運算子；表達不出來時**可以提案新運算子** |
| 產出 | 一張候選表 | 一張候選表 **+ 1043 筆有理由的成敗紀錄** |

**證據**：把兩邊的因子放進同一個回測比較，26 個自有因子勝過 25 個參考因子——
等權 6.07% vs 4.09%、Ridge 10.72% vs 8.90%（年化超額）。
**agent 挖到的不是已知因子的複製品。**
唯一例外是 LightGBM 那一列（13.74% vs 11.70%），
DFS 因子之間有較多可被樹模型利用的非線性交互。

兩邊的因子最後**合在一起用**最好（51 因子 + LightGBM，超額 16.36%）。
本專案把前置專案的因子當「參考因子」匯入，
一方面避免重新發明輪子，一方面讓比較是公平的。

## 挖礦引擎：自我進化怎麼運作，以及它是否真的在進化

```
        ┌─────────────────────────────────────────────────┐
        │                                                 │
   Generate ──→ 四階段漏斗 ──→ Distill ──→ learnings.md ──┘
   (LLM 提假設)   (本地驗證)   (LLM 寫檢討)      ↑
        │                                        │
        └──→ 表達不出來？ ──→ 運算子提案 ──→ 人工審核 ──→ dsl.py
                                                 │
                          每 10 輪：Consolidate（壓縮經驗 + 消化審計）
```

### 1. 受限 DSL：讓前瞻偏差「表達不出來」

因子公式不是自由的 Python，是一個 33 個運算子的受限語言。
**可用欄位、視窗長度、AST 深度全部是白名單**——
不是事後檢查有沒有偷看未來，而是**語言層面就寫不出來**。

```python
F-025  半導體毛利拐點股
  mul(cs_rank(d_gross_margin), industry_demean(cs_rank(op_margin)))
```

新增運算子時**必須**在 `tests/test_dsl_no_lookahead.py` 的 `FORMULAS`
加一條用到它的公式，否則 `test_all_operators_covered` 直接失敗。

### 2. 四階段漏斗：1043 個候選，26 個入庫（2.5%）

| 關卡 | 淘汰率 | 判準 |
|---|---|---|
| 語法／解析 | 0.7% | DSL 合法性、欄位白名單 |
| **Stage 1** IC | **47.4%** | 訊號強度門檻 |
| **Stage 2** 與因子庫去相關 | **28.3%** | ρ ≤ 0.5（含 25 個參考因子） |
| Stage 3 批次內去相關 | 0.5% | 同一輪的候選彼此 ρ ≤ 0.7 |
| **Stage 4** 品質 | **20.4%** | ICIR／衰減／多空腿／覆蓋率／換手 |
| **入庫** | **2.5%** | 18 個一般 + 8 個產業專屬（Stage 4b） |

Stage 4b 是產業專屬通道——只在單一產業有效的因子不該被全市場門檻擋掉。

### 3. 它真的在進化嗎？入庫率一路下滑，但下滑的原因才是重點

把 68 輪切成三段看，入庫率是 **4.2% → 2.6% → 0.9%**。
單看這條線像是 agent 越挖越差。但拆開各關卡的淘汰組成，結論相反：

| 區段 | 候選 | 語法 | **S1 IC** | **S2 去相關** | S3 | **S4 品質** | 入庫 |
|---|---|---|---|---|---|---|---|
| 前 1/3（輪 1-22） | 330 | 0.0% | **53.9%** | **12.1%** | 1.2% | **28.5%** | 4.2% |
| 中 1/3（輪 23-45） | 345 | 0.3% | 43.5% | 35.7% | 0.3% | 17.1% | 2.6% |
| 後 1/3（輪 46-68） | 345 | 1.7% | **44.9%** | **36.5%** | 0.0% | **15.9%** | 0.9% |

**S1（訊號強度）淘汰率從 53.9% 降到 44.9%，S4（品質）從 28.5% 降到 15.9%——
agent 提的假設變好了。** 同時 **S2（與既有因子重複）從 12.1% 暴增到 36.5%，三倍**。

**所以入庫率下滑是因子庫飽和，不是 agent 退步。**
瓶頸從「找得到訊號嗎」變成「找得到**新的**訊號嗎」——
每個新候選都得同時跟 51 個既有因子的相關度低於 0.5，這個門檻本來就會越來越難。

（語法錯誤從 0.0% 升到 1.7% 是唯一反向的指標：簡單的公式寫完了，
agent 開始嘗試更複雜的結構，偶爾寫壞。52 筆 DSL 表達限制被記錄下來。）

### 4. 兩層記憶：只進不出 vs 唯一注入

| 層 | 內容 | 進 prompt 嗎 |
|---|---|---|
| `attempts/` | 1043 筆完整軌跡：假設、公式、預測、實測、診斷 | ❌ 只進不出，供人查閱與審計 |
| `learnings.md` | 90 行、9.6KB 的蒸餾經驗 | ✅ **唯一**注入 Generate prompt 的記憶 |

分開的理由是 prompt 預算與訊號雜訊比。1043 筆原始紀錄塞不進 prompt，
塞得進也只會稀釋。**整理回合（每 10 輪）負責把它壓縮**：
升級／推翻／合併既有 lesson，原文自動備份到 `learnings_history/`（目前 4 份）。

`learnings.md` **可以直接手動編輯**。這是刻意的——
如果蒸餾出來的經驗品質差，人可以直接改，不必等下一輪。

### 5. 運算子提案：agent 可以擴充自己的語言

表達不出某個想法時，agent 可以提案新運算子，寫進 `operator_proposals.json`。
機械驗證只查名稱格式／純函數簽名／證據引用 ≥2，**不保證語意可用**——
例如 `qtr_only` 通過了驗證，但在月頻面板上會產生 100% NaN。
所以**人工批准前絕不自動實作**。

目前 **5 個提案上線、2 個否決**：
`rank_nz`、`industry_demean`、`streak`、`streak_true`、`clip_std`。

實作完要跑 `python src/unblock.py --apply`——
當初因為表達不出來而失敗的假設會被放回佇列重試，
否則那些已經付過診斷成本的候選就白白浪費。目前已解鎖 2 個、佇列消化 20 筆。

### 6. 成本

68 輪累計。最近一週 4 輪、504,717 tokens、**$3.24**（約 $0.81／輪），
其中 **51% 是輸出 token**（推理）。輪次／token／成本三種週預算都在
`config.yaml` 的 `budget` 區塊，跨 session 自動接續、每週一重置。

## 方法論：怎麼確保這些數字不是自己騙自己

一個漂亮的 IR 有很多種假法，每一種需要不同的方法拆穿。

### 1. 前瞻偏差：四層獨立防護，每一層都做過變異驗證

| 層 | 檔案 | 檢查什麼 |
|---|---|---|
| DSL 語言層 | `test_dsl_no_lookahead.py` | 33 個運算子逐一驗證 |
| 全管線 | `test_pipeline_no_lookahead.py` | 資料 → 漏斗 → 診斷 |
| 因子合成 | `test_factor_lab.py` | walk-forward + embargo、橫斷面標準化 |
| 市場狀態模型 | `test_hmm_regime.py` | 時點對齊、前向濾波、狀態標籤 |

共同手法：**汙染 cut 之後的資料，斷言 cut 之前的輸出位元級相同**（`check_exact=True`，不給容差）。

光有測試不夠——**測試本身也可能是假的**。每一道都做過變異驗證，故意寫錯確認它會轉紅：

```
把 walk_forward 的訓練窗改成全期       → test_walk_forward_no_lookahead              轉紅
把 embargo 拿掉                       → test_segments_embargo_gap                    轉紅
把 forward_filter 換成 predict_proba   → test_forward_filter_is_causal                轉紅
把 market_series 的 shift(1) 拿掉      → test_market_series_lags_observations_by_one  轉紅
```

這不是形式主義。專案初期就抓到 `test_pipeline_no_lookahead` 的汙染點寫死了 index、
落在 `sub_train` 內部——**測試自己在製造假陽性**，整套前瞻檢測形同虛設。

### 2. 密封的測試期

`library.json` 裡每個因子都有 `test_metrics_sealed`，**絕不進入任何 prompt**。
agent 只能看到 `sub_train` 與 `validation` 的指標。

### 3. 選擇偏誤：walk-forward 保護的是參數，不是「選哪些因子」

用 test 期的 IR 挑因子、再用 test 期的 IR 當成績，就是拿答案卷挑答案。
`--greedy` 因此拆成 `--select-span`（在哪裡挑）與 `--span`（在哪裡報）：

| 做法 | 挑選期 | test 期 IR | test 期超額 |
|---|---|---|---|
| **全部 26 個，不挑** | — | **1.583** | **10.72%** |
| 貪婪挑 k=3 | validation | 1.425 | 8.47% |
| ~~貪婪挑 k=10~~ | ~~test~~ | ~~2.264~~ | ~~12.04%~~ ← 假的 |

挑出來的組合在 validation 期 IR 高達 4.406，到 test 期只剩 1.425——
**那 4.4 是 24 個月樣本上的噪音**。結論是別挑。不帶 `--select-span` 時程式會印警告。

### 4. 過擬合統計量，以及它們的但書

```
Deflated Sharpe：0.997
  樣本外月數 T = 77　試驗數 N = 54（51 個單因子 + 3 個合成模型）
  主動報酬月 Sharpe 0.742（年化 2.57）　去膨脹門檻 SR0 = 0.398（年化 1.38）
PBO（CSCV，S = 12 切塊，C(12,6) = 924 組）：0.001
```

⚠️ DSR 必須用**主動報酬**（超額）而非原始報酬——
不減基準的話所有策略都吃同一份多頭 beta，試驗集的 Sharpe 變異被壓縮，門檻被低估，DSR 虛高。

> ⚠️ **PBO 0.001 要打折扣看。** 母體裡 51 個是單因子、只有 3 個是合成模型，
> 而合成模型在任何切塊都穩定勝過單因子，PBO 於是趨近 0。
> 它說明的是「合成勝過單因子」很穩健，**不是**「這組超參數沒過擬合」。
> 程式會在 PBO 過低時自動印出這段警告。

### 5. 一次真實的判讀錯誤：用 IR 去評判一個 beta 決策

這是本專案最值得記錄的一段，因為**沒有任何測試能抓到它**。

市場狀態切換模組原本被判定失敗：IR 從不切換的 1.74 掉到 1.08。
`TODO.md` 寫上「結案，結論是負面的」，`RESULTS.md` 第 11 節整節都在解釋它為什麼失敗。

**程式完全正確。** IR 算對了、beta 算對了、前瞻防護全部有效、測試全綠。
錯的是**拿 IR 去判斷一個 beta 決策**這個判讀層面的選擇。

IR = 超額 / 追蹤誤差，是**相對基準**的指標；而切換的本質是降低 beta。
在一段基準年化 +24.26% 的測試期裡，任何降 beta 的動作都會讓相對基準的超額下降，
IR 必然扣分——**即使那個動作在風險調整後是賺的**。

換成對曝險免疫的 Sharpe 之後，結論反轉（詳見下方）。診斷方式很簡單，
之後遇到任何「兩個指標打架」都適用：

1. **先確認 alpha 有沒有變。** 沒變就代表動到的是曝險，不是技術。
2. **把曝險調成一樣再比。** 加槓桿或減倉，然後看每一欄。
3. **看對曝險免疫的指標。** 相對指標不能用來評判刻意的曝險決策。
4. **算信賴區間。** 77 個月能不能分辨 1.79 與 1.88？答案是不能。

## 三個必須說出口的但書

**一、可交易性有代價。** 只看最流動 30% 的股票時：

| 版本 | 年化超額 | IR | 月勝率 | 下跌月最好 3 個月佔總超額 |
|---|---|---|---|---|
| 全體股票池 | 16.30% | 2.55 | 84.4% | 33% |
| 可交易版（最流動 30%） | 15.10% | **1.16** | **58.4%** | **58%** |

**超額的水準守得住，穩定度守不住。** 持股從 84 檔縮到 24 檔，
2022 與 2023 年小幅為負。而且下跌月的超額有 58% 來自最好的 3 個月
（2020-12、2020-02、2022-05，其中兩個在疫情初期）——
拿掉這 3 個月，下跌月 IR 從 1.34 崩到 **0.78**。**這是整套診斷裡最該記住的一格。**

對照之下全體股票池是廣泛的：27 個下跌月有 23 個超額為正，
中位數 +1.08% 與平均 +1.09% 幾乎相同，拿掉最好的 3 個月 IR 只從 2.78 掉到 2.42。

**二、六項檢定共用同一段歷史。** 它們互相獨立地檢查不同的失效模式，
但全都在 2020-01 ~ 2026-06 這 77 個月上做。**真正的樣本外只有一種：往前走。**

**三、沒有產業輪動、沒有市場擇時，永遠 100% 投資。**
回測逐月「在各產業內」取前 10%，產業權重結構性地鎖在全池比例上
（持股 60.6% 電子 vs 全池 59.9%，四個產業偏離都在 ±0.7% 內）。
全部超額都來自產業內選股這**單一**來源。

## 穩健性診斷（`src/ml_diagnose.py`）

| 假法 | 拆穿的方法 | 結果 |
|---|---|---|
| 只是搭上多頭順風車 | 分多空 régime | 下跌月超額 **+13.08%**（IR 2.78、t 4.17、勝率 85.2%），比上漲月的 IR 2.53 還高；七年逐年超額全正 |
| 只是少數幾個月撐起來 | 逐月攤開 + 拿掉最好 3 個月 | 全體 IR 2.78 → 2.42；可交易版 1.34 → **0.78** |
| 只是小型股／低流動溢酬 | 剔除底 70% 低流動股 | 超額仍有 **15.09%**（原 16.28%） |
| 只是規模因子換個名字 | 規模中性版重跑 | IR 2.57 → 2.14（−16.9%），**與「隨機拿掉一個重要因子」的中位掉幅 16.9% 相同** |
| 只是試很多策略挑到的幸運兒 | Deflated Sharpe / PBO | DSR **0.997**、PBO 0.001（有但書） |
| 報酬被換手成本吃光 | 成本敏感度 | 成本拉到 1.6%（設定值四倍）仍有 **6.68%** 超額；等權此時已翻負 |

規模代理的偵測用了**兩道判準**：相關度與公式。
F-013 `sub(cs_rank(rev_yoy), cs_rank(amt_21))` 與
F-020 `mul(cs_rank(op_margin), cs_rank(neg(amt_21)))`
公式裡明明白白寫著 `amt_21`，量測相關度卻低於 0.6 門檻。
**相關度是行為證據，公式是定義證據，兩道都要。**

**留一法的擁擠度訊號**：26 個自有因子（全集 IR 1.583）只有 5 個是拖累者，
主要支柱是 F-026 金控效率重估（Δ **+0.417**）。
但 51 個因子的 all 組被標成拖累的有 **33/51**——那不代表 33 個是垃圾，
而是這組因子**過度擁擠**，邊際貢獻趨近零、正負號落在噪音裡。
此時該讀的是**排序**而非正負號。這與上面「S2 淘汰率暴增」講的是同一件事。

### 只做多——以及一條沒人讀的腿

| 腿 | CAGR | Sharpe | MaxDD | 目前 |
|---|---|---|---|---|
| `long` | 45.54% | 1.92 | −16.66% | ✅ 所有 headline |
| `long_short` | 36.69% | **2.63** | **−9.82%** | ❌ 算了但沒人讀 |
| `benchmark` | 24.26% | 1.18 | −17.73% | ✅ 只用來算超額 |

空頭腿單獨看年化 **−7.87%**——後段班相對基準每年輸 16.05%、78% 的月份都輸（訊號很強），
但絕對報酬仍是正的。**單獨放空賺不了絕對報酬，它的價值在對沖。**
台股放空另有借券成本與平盤下不得放空的限制，這條腿尚未納入成本模型。

## 市場狀態模型（`src/hmm_regime.py`）——應用層的一條支線

Gaussian HMM 判斷下個月是多頭態還是空頭態，用途**不是決定進出場**，而是**切換因子組**。
它消費因子庫，不產生因子，跟上面的挖礦迴圈沒有關係。

**為什麼是切換因子而不是擇時**：test 期有 65% 的月份上漲，「永遠猜漲」就有 65% 準確率
且績效等同滿倉；要贏過滿倉需要 **80%** 的方向準確率。
切換因子的門檻低得多，因為**失敗的代價低一個量級**——
進出場猜錯 = 整月不在場；因子權重猜錯 = 用了比較不合適的那組因子（IC 仍為正）。

而且有結構可用：低波動族群在下跌月的 ICIR **t 值高達 8~12**、上漲月貼近零，
這個不對稱在分類期與 test 期**都成立**。防禦組 = 依分類期下跌月 t 值取前 8 個，**不看 test 期**。

### 結果：以 Sharpe 論達標，但差距不顯著

| | beta | alpha | CAGR | **Sharpe** | IR | MaxDD |
|---|---|---|---|---|---|---|
| 靜態：全部因子 | 0.932 | +13.27% | 39.32% | **1.79** | 1.74 | −15.59% |
| 靜態：只用防禦組 | 0.711 | +9.75% | 28.82% | 1.74 | 0.35 | −13.16% |
| **HMM 切換（樣本外）** | 0.791 | +13.52% | 35.80% | **1.88** | 1.08 | −13.16% |
| 完美預知（上限） | 0.874 | +16.97% | 42.82% | **2.01** | 1.98 | −13.16% |

**兩個指標指向相反方向**：IR 說切換輸，Sharpe 說切換贏，且 **1.79 < 1.88 < 2.01**
落在驗收區間內。切換的超額少了 3.11pp，其中 3.41pp 來自 beta 貢獻更負，
**alpha 反而多了 0.25pp——切換沒有傷到 alpha，只是賣掉了 beta**。

**等 beta 對照**（放大 1.178 倍拉回 beta 0.932）：CAGR **42.86%** vs 39.32%、
IR **1.80** vs 1.74、MaxDD −15.50% vs −15.59%。**每一欄都不輸。**

**但這個差距分不出來。** 配對自助法 10000 次：
ΔSharpe = −0.091，95% CI **[−0.347, +0.152] 跨越 0**，逐月報酬差配對 t = 1.34。
正確措辭是 **「沒有證據顯示切換比較差，也沒有足夠證據顯示它比較好」**。

另外兩件不能只講好消息的事：**MaxDD 的 2.4pp 改善等 beta 後消失**
（是曝險效果不是擇時效果，把靜態縮到 0.79 倍就有）；
**1.178 倍要真的借錢**（以 3% 計約吃掉 0.53pp/年）。

### 門檻掃描與總經消融

純價格版的五個門檻（0.1 / 0.2 / 0.3 / **0.5 預設** / 0.7）Sharpe 分別是
1.82 / 1.95 / 1.89 / **1.88** / 1.85，**全部勝過基準 1.79**；
而 IR 在同一批設定上是 1.28 / 1.34 / 1.13 / 1.08 / 0.98，**全部落後 1.74**。
兩個指標在五個獨立參數點上系統性反向。
⚠️ 不要挑 @0.2 的 1.95 來用——那是 `--greedy` 選擇偏誤的翻版。
該引用的是未調過的預設值 **0.5 → 1.88**。

抓了景氣對策信號、領先指標、M1B/M2 共 3992 列月頻資料做消融，
Sharpe 依序是純價格 **1.88** > ＋燈號 1.84 > ＋信號分數 1.82 > ＋M1B−M2 1.78 >
＋全部總經 1.76 > ＋領先指標 1.73 > 只用總經 1.68。
**每個加總經的版本都比純價格差，加得越多越差。**
純價格的 seed 全距是 0.00，加總經的是 ±0.03（比它們與基準的差距還大）。
合理的解釋是發布落後：月底換股時最多只能用 t−1 月的燈號，而燈號本身就是落後指標的合成。

### 三道前瞻紀律，以及一個非直覺的發現

1. **時點對齊**：`obs_ret[t] = mkt[t−1]`。少 shift 一格就是直接看答案。
2. **只用前向濾波**：`hmmlearn.predict()`（Viterbi）與 `predict_proba()`（平滑）
   都會用整段序列回推狀態。本模組**只用 hmmlearn 擬合參數**，狀態推論自己寫遞迴。
3. **參數與標籤只在訓練窗擬合**。

**狀態標籤不能望文生義**：訓練期擬合出的「低報酬高波動」狀態，
下個月市場報酬反而是 **+2.56%、72.0% 上漲**（另一態是 +0.40%、61.8%）。
第一版照直覺命名，test 期方向準確率只有 **35.1%**、t = **−2.33**、p = 0.023——顯著地**反向**。
那不是模型無效，是標籤貼反了。修正後改用訓練期的後續報酬決定。

總經資料的發布落後寫進資料結構本身（`ym` vs `pub_ym`），
**新增欄位若忘了在 `PUB_LAG_MONTHS` 登記會直接丟錯**——
因為前瞻偏差不會報錯，只會讓回測變好看。

`--span` 預設 `test`，而且**只有 `test` 是真正的樣本外**——
agent 的因子是用 `sub_train` + `validation` 選出來的，
上游 DFS 因子也是用 ≤2019-12 篩的，兩邊 test 期起點相同，比較才公平。選其他期會跳警告。

## 已知的限制

1. **因子庫已接近飽和**。S2 淘汰率 36.5%、留一法標出 33/51 拖累者。
   繼續挖的邊際報酬遞減，下一步該是換問題（產業輪動、`long_short`）而非加因子。
2. **HMM 的優勢不顯著**（ΔSharpe 的 95% CI 跨越 0）。需要更長樣本才能定案。
3. **`long_short` 未納入借券成本**與平盤下不得放空的限制，那條 Sharpe 2.63 要打折。
4. **美債殖利率曲線取不到**。FinMind 的 datalist 認得 `United States 10-Year`
   （官方文件寫成 `10-Year`），資料端點卻回空陣列，判定為方案層級或額度限制。
5. **所有檢定共用同一段 test 期**。往前走才是真的樣本外。
